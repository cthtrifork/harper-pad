# Architecture

How the pieces fit. Details live in the other docs: [storage](storage.md), [security](security.md), [pages](pages.md),
[self-update](self-update.md), [windows](windows.md).

## One frontend, two hosts

The same Vue 3 + Vite frontend runs in two builds:

| Build | Host | Data |
|---|---|---|
| Desktop (`vite build`) | A Wails v3 window (GTK4 + WebKitGTK on Linux, WebView2 on Windows) | SQLite, through the Go service |
| Web (`vite build --mode web`) | The browser, published to GitHub Pages | IndexedDB |

`frontend/src/lib/backend.ts` is the only file that knows which build it is in. Everything else calls it for drafts,
settings, saving files and the version; the desktop bindings are imported on demand, so the web bundle has no Wails code.
`make build-server` produces a headless build that serves the same frontend over HTTP, used by CI, the screenshots and
Lighthouse.

## Go side

- `main.go` embeds `frontend/dist`, creates the Wails app with the services from `app.NewServices()`, starts the updater and
  opens the window and tray.
- `internal/app` holds the services, the only bindings the frontend calls (`frontend/bindings` is generated by `make bindings` and
  committed). Drafts and settings share one database holder (`database.go`), which `DraftService` closes on quit. `SyncService` has no
  network and no secrets: the sync client runs in the page.
- `internal/store` is the database ([storage](storage.md)); `internal/selfupdate` is the in-app updater's GitHub-release provider.

Build tags change what is compiled in: `server` (headless, no GTK), `production` (release), and the development-only `mcp`
and `pprof`, which `production` rejects.

## Frontend

- `App.vue` composes the header, the editor, the Problems panel, the status bar and the drafts drawer.
- `internal/app/assets.go` is the Wails `AssetOptions.Middleware` (Wails has no built-in compression or cache headers): gzip for text assets (headless server builds only; the native window gets plain bytes) and `Cache-Control` (immutable for the content-hashed `/assets/*`, `no-cache` for `index.html`).
- `lib/harper.js` starts Harper in its own Web Worker (`lib/harperWorker.js`, WebAssembly) after the first paint; the page
  talks to it with plain messages. The worker turns its lints into plain objects, so no wasm-backed value is held by Vue or
  CodeMirror. It does not use harper.js's `WorkerLinter`: that also builds a serializer on the main thread, which fetched
  and compiled the 20 MB wasm a second time on the page and was most of Lighthouse's blocking time (TBT).
- `lib/editor/` is the CodeMirror 6 editor: the lint source (`lint.js`, debounced), theme, markdown or plain text mode,
  status bar statistics and the problems list.
- `lib/useDrafts.js` is the draft state: autosave shortly after typing and on blur or hide, the link from a draft to a file
  on disk, and the list the drawer shows. `lib/statusLine.ts` joins that state with the sync state into the one status line in the status bar
  (the Sync button in the header only acts; the sync chip only shows the connection).
- Sync (optional, both builds; the rules are in [sync](sync.md)): `lib/syncRun.js` (`createSyncer`) is the one place a draft is synced and
  decided. `lib/desktopSync.ts` and `lib/webDrafts.js` give it the same drafts store on both builds.
  `lib/useSync.js` is the state behind the status bar chip (`SyncChip.vue`), and `lib/csp.ts` builds the page's policy, which names the sync
  server when `SYNC_ORIGIN` is set.
- `Preview.vue` renders markdown for the Split and Preview views (`marked` parses it); text from drafts or Harper never goes
  through `v-html` or `innerHTML`. `CodeBlock.vue` colours fenced code (`sh`/`bash`, `json`, `yaml`, `toml`) with the lazy parsers in `lib/highlight.ts`, as spans of text; other languages stay plain. To add one, add a loader and aliases there. `lib/editor/snippets.js` expands a trigger alone on a line (`<code>`, `<sh>`, `<json>`, `<yaml>`, `<toml>`, `<todo>`, `<table>`, `<link>`, `<img>`) when Enter is pressed; to add one, add a line to its `SNIPPETS` table; `SnippetsHelp.vue` (the drafts drawer's footer link "Snippets") draws the help page from the same table, and pressing a card there inserts that snippet at the cursor (`insertSnippet`).
- `ToastBar.vue` is the one toast (a message and one action: Undo), used for autocorrect's "Fixed N things" and for what sync says.
  `ConflictDialog.vue` is the one modal for a conflict ([sync](sync.md#the-keep-or-overwrite-dialog)), and `DeletedElsewhereDialog.vue` a
  forced Keep or Remove for a draft deleted on another device (`docs/design-cheatsheet.html` lists them as the exceptions to "no modals").
- Styles are plain CSS, one file per component, in `frontend/src/styles`.

## Data flow

1. Typing updates the CodeMirror document; the lint source debounces and asks the Harper worker for lints.
2. Lints become diagnostics in the editor and rows in the Problems panel. Applying a fix is a normal edit.
3. The same edit schedules a draft save through `backend.ts`: `DraftService.SaveDraft` on desktop, IndexedDB on the web.
4. "Save to disk" writes the draft's text to disk (the Go service with a native dialog on desktop, the browser's file picker
   on the web) and keeps the path on the draft.
5. With sync on (either build), `useSync` asks `createSyncer` to sync the draft and, at other moments, every draft; [sync](sync.md#sync-moments) says when.
